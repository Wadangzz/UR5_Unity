# 데모 / 튜닝 가이드

UR5 웹 시뮬레이터를 굴려보며 각 제어 개념을 눈으로 확인하는 레시피 모음.
값은 모두 실측으로 안정/발산을 확인한 것. (백엔드 `cd backend && uv run main.py`,
프론트 `cd frontend && pnpm dev` 둘 다 띄우고 브라우저에서.)

---

## 빠른 시작

> 제어기 **PD** · 게인 기본(Kp=100, Kd=20) · 궤적 **관절공간** · 제어율 **1000Hz** · 나머지 0
> → Run (정상 동작) → **제어율만 500Hz로** 낮춰 다시 Run → **발산** 확인.
> "같은 게인인데 제어율 낮추니 터진다" = 이 시뮬의 핵심 (sim-to-real).

---

## 안정성 참고표 (실측)

### 제어기 × 제어율 (기본 게인)

| 제어기 | 게인 | 연속 | 1000Hz | 500Hz |
|---|---|---|---|---|
| PD | Kp=100, Kd=20 | ✓ | ✓ | 발산 |
| Computed Torque | Kp=100, Kd=20 | ✓ | ✓ | (가장 강건) |
| PID | Kp=120, Ki=80, Kd=35 | ✓ | **발산** | — |
| 임피던스 | K=600, D=60 | ✓ | **발산** | — |

→ **PID·임피던스는 hot 해서 이산이면 2000Hz 필요.** PD·CT 는 1000Hz OK.

### 자동튜닝 정착시간 → 필요 제어율 (PD)

극배치: `ωn = 4/ts`, `Kp = ωn²`, `Kd = 2ωn`

| 정착 ts | 게인 (Kp,Kd) | 연속 | 2000Hz | 1000Hz | 500Hz |
|---|---|---|---|---|---|
| 0.2s | 400, 40 | ✓ | ✓ | 발산 | 발산 |
| 0.3s | 178, 27 | ✓ | ✓ | ✓ | 발산 |
| 0.5s | 64, 16 | ✓ | ✓ | ✓ | ✓ |
| 0.6s | 44, 13 | ✓ | ✓ | ✓ | ✓ |

→ **빠른 정착(높은 게인)일수록 높은 제어율 필요.** 발산은 버그가 아니라
"이 목표면 제어보드가 몇 Hz 는 돼야 한다"를 알려주는 것.

## A. 제어율 / 이산 (sim-to-real)

### ① 제어율 절벽 ★대표
- 제어기 **PD**, 게인 기본, 궤적 관절, 마찰/노이즈/외란 0
- 제어율을 **연속 → 1000 → 500** 순으로 Run
- 👀 연속·1000 정상, **500Hz 발산**. 게인 안 바꿨는데 제어율만으로.

### ② 자동튜닝 vs 제어율
- 제어기 **PD**, **자동튜닝 ON**, 제어율 **1000Hz**
- 목표 정착시간 **0.2s → 0.3s → 0.5s**
- 👀 0.2s(Kp=400) 발산, 0.3s 안정. "공격적 튜닝은 더 빠른 제어보드 필요."

### ③ 센서 노이즈 → D항 증폭
- 제어기 **PD**, 제어율 **1000Hz**, 궤적 관절
- 노이즈 **0 → 0.005 → 0.02** (rad, 측정오차 크기)
- 👀 토크 그래프 chatter↑. Kd 를 **20 vs 60** 으로 → 높은 Kd 에서 chatter 심함.
- 참고: 노이즈는 **이산 전용**(연속이면 비활성). rad=크기, 빈도는 제어율(Hz).

---

## B. 컴플라이언스 (외란 반응)

### ④ 임피던스 — "밀면 밀린다"
- 제어기 **임피던스** (K=600, D=60), 제어율 **연속**(또는 2000Hz)
- 외란 **Fx = 40~80 N**
- 👀 모션 후 끝단이 외력 방향으로 밀림(Δx≈F/K). K=300↔1200 → 밀림 2배↔절반.

### ⑤ 어드미턴스 — 가상질량 오버슛
- 제어기 **어드미턴스** (M=4~8, B=15, K=600), 외란 **Fx=40**
- 👀 외력에 **2차 진동(오버슛)**. B 낮을수록(ζ작음) 출렁임 심함. (기구학 — 제어율 무관)
- 임피던스(밀림)와 어드미턴스(힘 읽고 능동 양보) = 컴플라이언스의 두 얼굴.

## C. 현실 한계

### ⑥ 마찰 — PD 처짐 vs PID 회복
- friction **15** (N·m), 궤적 관절
- **PD @1000Hz** → 정상상태 처짐(sse 큼) / **PID @2000Hz** → I항이 회복
- 👀 "왜 적분(I)이 필요한가" 체감.

### ⑦ 토크 포화 — 액추에이터 한계
- 제어기 **Computed Torque** (Kp=150, Kd=25), 제어율 연속
- 토크 한계 **40 → 20** 낮추기
- 👀 40 굼뜸(미정착), **20 발산**. 토크 그래프가 ±한계에 납작하게 잘림.

### ⑧ 모델 불확실성 — 제어기 선택 이유
- 페이로드 **3kg**, 모델 질량배율 **0.8** (컨트롤러가 로봇을 잘못 앎), 연속
- **PD** 처짐 / **PID** 회복 / **CT** 모델오차만큼 흔들림
- 👀 세 제어기 sse 비교 = "왜 PID/CT 를 쓰나".

---

## D. 궤적 / 제어기

### ⑨ resolved_rate + 직교 직선
- 제어기 **resolved_rate** (Kp=3), 궤적 **직교 직선(task)** vs **관절공간**
- 👀 task=말단 직선, joint=곡선. (시작이 특이점이면 task 는 "실행불가" 표시 — ready 출발이라 보통 OK)

### ⑩ PID 적분 발산여유 (Routh)
- 제어기 **PID**, 연속, Kp=120, Kd=35, **Ki 80 → 300**
- 👀 배지 **적분여유 Ki/(Kp·Kd)** > 1 이면 "발산위험" 빨강 → Run 시 진동/발산.
  (Routh 안정조건 Ki < Kp·Kd 시연)

## ⚠️ 주의

- **PID·임피던스 + 이산**은 1000Hz 면 발산 → **2000Hz 또는 연속**으로. (버그 아님)
- **노이즈**는 이산 전용 (연속이면 슬라이더 비활성).
- **홈(전관절 0)은 특이점** — task 궤적 출발점으로 부적합. Run/프로그램은 **ready 자세**에서 출발.
- 이산 모드는 numba JIT 동역학으로 1kHz ~수 초. 연속(기본)은 ~0.3s.
