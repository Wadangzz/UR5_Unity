# 로봇 동역학(Dynamics)과 역동역학(Inverse Dynamics) 정리

> 이 문서는 이 프로젝트(UR5, screw theory 기반)에 **동역학과 제어**를 붙이기 위한
> 기초 도메인 정리입니다. 이미 구현된 `MyRobotMath.SE3` 클래스(`skew`, `adjoint`,
> `matexp`, `matFK`, `body_jacobian`)와 연결해서 설명합니다.
> 표기는 *Modern Robotics* (Lynch & Park) 컨벤션을 따릅니다.

---

## 0. 한눈에 보는 지도

```
기구학(Kinematics)              동역학(Dynamics)
─────────────────             ─────────────────
위치/속도만 다룸                힘/토크/질량/관성까지 다룸
"어디에 있나?"                  "왜 그렇게 움직이나?"

  FK : θ      → x              순동역학 : τ      → θ̈   (시뮬레이터/plant)
  IK : x      → θ              역동역학 : θ,θ̇,θ̈ → τ   (제어기/토크 계산)
  J  : θ̇      → ẋ
```

- **이미 가진 것**: FK, IK, Jacobian (전부 기구학)
- **추가할 것**: 동역학 — 질량·관성·중력을 고려한 토크 계산

---

## 1. 왜 동역학이 필요한가?

지금 이 프로젝트는 "관절 각도를 계산해서 그 각도로 모델을 돌린다"입니다.
즉 **로봇이 무게도 없고 관성도 없는 유령**처럼 움직여요. 실제 로봇은:

- 팔이 무거우면 **중력 때문에 아래로 처집니다** → 버티려면 토크가 필요
- 빨리 움직이면 **관성 때문에 더 큰 토크**가 필요
- 한 관절을 돌리면 **다른 관절이 끌려가는 상호작용**(Coriolis)이 생깁니다

이런 걸 수식으로 표현한 게 **동역학 방정식**이고,
"원하는 움직임을 만들려면 각 관절에 토크를 얼마나 줘야 하나?"에 답하는 게
**역동역학(inverse dynamics)**입니다. 그리고 그 토크를 실제로 주면서
오차를 잡는 게 **제어(control)**예요.

---

## 2. 동역학 방정식 (Manipulator Equation)

로봇 동역학은 결국 이 한 줄로 요약됩니다:

```
τ = M(θ) θ̈  +  C(θ, θ̇) θ̇  +  g(θ)
```

| 기호 | 이름 | 물리적 의미 | 비유 |
|------|------|-------------|------|
| `τ` | 관절 토크 (n×1) | 각 모터가 내야 하는 힘 | 우리가 구하려는 답 |
| `M(θ)` | **질량행렬** (n×n) | 자세에 따라 변하는 "관성" | 무거운 물체일수록 큼 (F=ma의 m) |
| `θ̈` | 관절 가속도 | 얼마나 빨리 속도를 바꾸나 | F=ma의 a |
| `C(θ,θ̇)θ̇` | **코리올리/원심항** | 관절들이 서로 끌어당기는 효과 | 회전목마 위에서 걸을 때 휘청이는 힘 |
| `g(θ)` | **중력항** | 중력을 버티는 데 필요한 토크 | 팔을 수평으로 들고 있을 때 어깨 힘 |

### 각 항을 직관적으로

**① 질량행렬 M(θ) — "관성"**
- 1자유도라면 그냥 `τ = m·a`. 다자유도면 `m`이 행렬 `M`이 됩니다.
- `θ`에 따라 값이 변합니다. 팔을 쭉 뻗으면(관성↑) 큰 값, 접으면 작은 값.
- 항상 **대칭(symmetric)이고 양의 정부호(positive definite)** → 항상 역행렬 존재 → 나중에 순동역학에서 중요.

**② 중력항 g(θ) — "버티는 힘"**
- 속도·가속도가 0이어도(가만히 있어도) 필요한 토크.
- 팔을 수평으로 뻗고 멈춰 있으려면 어깨가 계속 힘써야 하죠? 그게 `g(θ)`.
- **가장 먼저, 가장 쉽게 구현/검증 가능**한 항 (제어 입문용 "중력 보상").

**③ 코리올리/원심항 C(θ,θ̇)θ̇ — "속도 때문에 생기는 힘"**
- `θ̇`(속도)의 제곱에 비례 → 빠를 때만 중요, 느리면 거의 무시 가능.
- 한 관절의 회전이 다른 관절에 만드는 가상의 힘. 다관절 로봇 특유의 "꼬임".
- 가장 직관이 안 오는 항이지만, 다행히 **계산은 자동으로 따라 나옵니다**(아래 RNE).

> 💡 **핵심**: 이 세 항을 직접 손으로 유도하면 지옥입니다(라그랑지안 미분...).
> 그래서 **Newton-Euler 재귀 알고리즘(RNE)**으로 *수치적으로* 한 방에 구합니다.

## 3. 순동역학 vs 역동역학

같은 방정식을 어느 쪽으로 푸느냐의 차이입니다:

```
역동역학 (Inverse Dynamics)               순동역학 (Forward Dynamics)
"이렇게 움직이려면 토크 얼마?"             "이 토크 주면 어떻게 움직이나?"

입력: θ, θ̇, θ̈                            입력: θ, θ̇, τ
출력: τ                                   출력: θ̈

τ = M θ̈ + C θ̇ + g                        θ̈ = M⁻¹ (τ − C θ̇ − g)
       ↑ 그냥 대입                              ↑ M의 역행렬 한 번
```

- **역동역학** = 제어기가 토크를 계산할 때 사용 (RNE로 바로 계산)
- **순동역학** = 시뮬레이터(plant)가 다음 상태를 계산할 때 사용
  - Unity가 없으면 **이 순동역학이 Unity를 대신하는 가상 로봇**이 됩니다.
  - 위 식처럼 **역동역학으로 M,C,g를 구한 뒤 한 번 뒤집으면** 순동역학이 공짜로 나옵니다.

## 4. 모든 것의 출발점: 단일 강체의 Newton-Euler

다관절로 가기 전에, **물체 하나**의 운동 법칙부터. 고등학교 물리의 확장입니다.

- **Newton (병진)**: `f = m·a` — 힘 = 질량 × 선가속도
- **Euler (회전)**: `m = I·ω̇ + ω × (I·ω)` — 토크 = 관성×각가속도 + 자이로 효과

여기서 회전 쪽 `ω × (I·ω)` 항이 바로 "빠르게 돌면 생기는" 비선형 효과입니다.

### screw(twist/wrench)로 묶기 — 여러분 코드와 연결되는 지점

Modern Robotics에서는 병진+회전을 **6차원 벡터 하나**로 묶습니다.
여러분이 이미 `B_tw`(body twist)로 쓰고 있는 그 표현이에요.

```
twist   V = (ω, v)   ∈ ℝ⁶   — 6D 속도 (각속도 3 + 선속도 3)
wrench  F = (m, f)   ∈ ℝ⁶   — 6D 힘   (모멘트 3 + 힘 3)
```

그러면 단일 강체의 운동 방정식이 깔끔한 한 줄이 됩니다:

```
F = G·V̇  −  [ad_V]ᵀ · G · V
```

- **`G`** = 공간 관성 행렬(spatial inertia matrix), 6×6:
  ```
  G = ┌ I₃ₓ₃(관성텐서)   0   ┐      I_b : 무게중심 기준 3×3 관성 텐서
      └      0        m·I₃ ┘      m   : 링크 질량
  ```
  → **이게 우리가 새로 넣어줘야 할 물리 파라미터** (UR5 URDF에 공개되어 있음)

- **`[ad_V]`** = small adjoint (Lie bracket), 6×6. `ω × (I·ω)` 같은 비선형 항을 만드는 연산:
  ```
  [ad_V] = ┌ [ω]   0  ┐       [ω], [v] 는 skew 행렬
           └ [v]  [ω] ┘       → 여러분의 se3.skew() 재사용!
  ```

> 📌 **여러분이 추가해야 할 새 primitive는 딱 둘**:
> 1. `ad(V)` 함수 (위 식, `skew` 재활용 → 약 5줄)
> 2. 링크별 `G_i` (질량·관성 데이터 입력)
>
> `adjoint`, `skew`, `matexp`는 이미 있는 걸 그대로 씁니다.

## 5. RNE — Recursive Newton-Euler 알고리즘

다관절 로봇 전체의 토크를 구하는 표준 알고리즘. **두 번 훑으면 끝**입니다.

```
        base (고정)                          tip (말단)
          ●────●────●────●────●────●────● (end-effector)
         관절1  2    3    4    5    6

  ① Forward pass  (base → tip)  : 속도 V_i, 가속도 V̇_i 를 전파
  ② Backward pass (tip → base)  : 힘/렌치 F_i 를 거꾸로 전파 → 토크 τ_i 추출
```

### ① Forward pass (base → tip): "각 링크가 얼마나 빠르고 급하게 움직이나"

base부터 시작해서 관절을 하나씩 지나며 속도·가속도를 누적합니다.

```
V_i  = Ad(T_{i,i-1}) · V_{i-1}  +  A_i · θ̇_i
V̇_i  = Ad(T_{i,i-1}) · V̇_{i-1}  +  [ad_{V_i}] · A_i · θ̇_i  +  A_i · θ̈_i
```
- `A_i` : 링크 i 좌표계에서 본 관절 i의 screw 축 (여러분의 `B_tw`와 같은 종류)
- `Ad(T_{i,i-1})` : 이전 링크 속도를 현재 링크 좌표계로 옮기는 변환 → **`se3.adjoint()` 그대로 사용**
- `T_{i,i-1}` : `se3.matexp()`로 계산 (FK에서 하던 것과 동일)

> 🪄 **중력 트릭**: base의 초기 가속도를 `V̇_0 = (0,0,0, 0,0,g)` 로 둡니다
> (마치 로봇 전체가 위로 `g`만큼 가속되는 것처럼). 그러면 중력이 별도 항 없이
> **자동으로 토크에 반영**됩니다. 따로 `g(θ)`를 유도할 필요가 없어요.

### ② Backward pass (tip → base): "각 관절이 얼마의 힘을 받나"

말단에서 시작해 거꾸로 내려오며, 각 링크에 작용하는 렌치를 누적합니다.

```
F_i = Ad(T_{i+1,i})ᵀ · F_{i+1}  +  G_i · V̇_i  −  [ad_{V_i}]ᵀ · G_i · V_i
τ_i = F_iᵀ · A_i        ← 렌치를 관절 축에 투영하면 그 관절의 토크!
```
- 끝(tip)에서 외력이 없으면 `F_{n+1} = 0`에서 시작
- 마지막 줄 `τ_i = F_iᵀ A_i` 가 우리가 원하던 **관절 토크**

이게 전부입니다. `(θ, θ̇, θ̈)`를 넣으면 `τ`가 나옵니다. → **역동역학 완성.**

## 6. M, C, g를 RNE에서 "뽑아내기"

제어를 하려면 세 항을 따로 알아야 합니다. RNE를 영리하게 호출하면 전부 분리됩니다:

```python
# RNE(θ, θ̇, θ̈, 중력여부) 가 있다고 하면:

g(θ)        = RNE(θ, 0,  0,  중력 ON)     # 속도·가속도 0 → 중력만 남음
M(θ)의 i열  = RNE(θ, 0,  eᵢ, 중력 OFF)    # i번째만 단위가속도 → M의 한 열
C(θ,θ̇)θ̇    = RNE(θ, θ̇, 0,  중력 OFF)     # 가속도 0, 중력 OFF → 코리올리만
```
- `eᵢ` = i번째만 1인 단위벡터. 이걸 n번 호출하면 `M`의 전체 열이 채워짐.
- 즉 **RNE 함수 하나만 잘 짜면 M, C, g가 전부 파생**됩니다.

## 7. 제어(Control)와의 연결

M, C, g가 손에 들어오면 제어 법칙은 레고처럼 조립됩니다 (쉬운 순):

```
① PD + 중력보상  (가장 쉬움, 입문용)
   τ = Kp·e + Kd·ė + g(θ)
   → 중력만 상쇄하고 스프링-댐퍼로 목표 자세 잡기. 안정성 보장됨.
   e = θ_목표 − θ (오차)

② Computed Torque  (궤적 추종, 강력)
   τ = M(θ)·(θ̈_d + Kd·ė + Kp·e) + C·θ̇ + g
   → 비선형 동역학을 통째로 상쇄 → 오차가 ë + Kd·ė + Kp·e = 0 으로 선형화

③ Task-space / Impedance  (말단을 스프링처럼)
   → 이미 가진 body Jacobian J 를 이용해 Cartesian 공간에서 직접 제어
```

게인은 직관적으로: `Kp = ωₙ²`, `Kd = 2ζωₙ` (ωₙ=반응 속도, ζ=감쇠비).

## 8. Unity 없이 Python만으로 닫는 루프

순동역학을 적분기로 돌리면 그 자체가 가상 로봇(plant)입니다:

```python
dt = 0.002
for k in range(N):
    tau   = control_law(θ, θ̇, θ_d, θ̇_d, θ̈_d)        # ← 역동역학(제어기)
    θ̈     = solve(M(θ), tau − C(θ,θ̇)·θ̇ − g(θ))      # ← 순동역학(plant)
    θ̇    += θ̈ * dt                                   # 적분 (semi-implicit Euler)
    θ    += θ̇ * dt
    log(θ, tau, error)                                # 나중에 matplotlib 플롯
```

- 시각화는 기존 `matFK`로 관절 위치를 뽑아 matplotlib 3D로 그리면 됩니다.
- 정밀도가 필요하면 적분을 `scipy.integrate.solve_ivp`(RK45)로 교체.

## 9. 용어 빠른 참조

| 용어 | 뜻 |
|------|----|
| **DOF** | 자유도. UR5는 6 |
| **twist `V=(ω,v)`** | 6D 속도 (각속도+선속도). 여러분의 `B_tw`가 screw축 |
| **wrench `F=(m,f)`** | 6D 힘 (모멘트+힘) |
| **spatial inertia `G`** | 6×6 관성 행렬 = diag(관성텐서, 질량) |
| **`Ad_T` (big adjoint)** | twist/wrench를 다른 좌표계로 옮김. `se3.adjoint()` ✅ 있음 |
| **`ad_V` (small adjoint)** | Lie bracket. 비선형(코리올리) 항 생성. ❌ 추가 필요 |
| **RNE** | Recursive Newton-Euler. 토크 계산 2-pass 알고리즘 |
| **순동역학(FD)** | τ→θ̈. 시뮬레이터 |
| **역동역학(ID)** | θ,θ̇,θ̈→τ. 제어기 |
| **중력보상** | g(θ)를 상쇄해 무중력처럼 만드는 가장 기본 제어 |

## 부록 A. Lie군 구조 — 군 vs 대수, exp/log, 그리고 "회전의 로그 = skew"

이 프로젝트의 수학 라이브러리(`MyRobotMath.py`)는 수학적 객체에 따라
`SO3` / `SE3` / `Kinematics` 로 분리되어 있습니다. 그 바탕이 되는
**Lie 군(group)과 Lie 대수(algebra)** 구조를 정리합니다.

### A.1 네 가지 객체: 군 vs 대수

| | **군 (Group)** — "자세/위치" | **대수 (Algebra)** — "속도/접선" |
|---|---|---|
| **회전만** | **SO(3)**: 회전행렬 R (3×3, RᵀR=I, det=1) | **so(3)**: 반대칭행렬 [ω] (≅ ω∈ℝ³) |
| **회전+병진** | **SE(3)**: 변환행렬 T=[[R,p],[0,1]] (4×4) | **se(3)**: twist V=(ω,v)∈ℝ⁶ (screw) |

- **군** = "어디에 있나"(configuration), 휘어진 다양체(manifold)
- **대수** = "어떻게 움직이나"(velocity), 평평한 벡터공간(tangent space)
- 둘을 잇는 다리가 **exp / log** 입니다:

```
   so(3) ──exp──▶ SO(3)            se(3) ──exp──▶ SE(3)
  ([ω]=skew)◀─log── (R)          (twist V) ◀─log── (T)
```

코드 대응: `SO3.exp`/`SO3.log`, `SE3.exp`/`SE3.log`.

### A.2 핵심: 회전을 로그하면 skew-symmetric (= so(3))

회전행렬 `R ∈ SO(3)` 의 행렬 로그는 **반대칭(skew-symmetric) 행렬**이고,
그게 바로 Lie 대수 `so(3)` 의 정의입니다.

`SO3.log` 의 구현을 보면 핵심이 드러납니다:

```python
return theta / (2 * np.sin(theta)) * SO3.vee(R_mat - R_mat.T)
#                                            └──────┬──────┘
#                                          (R − Rᵀ) = 항상 반대칭
```

**왜 반대칭인가** — 임의의 행렬에서 그 전치를 빼면 항상 반대칭이 됩니다:

```
(R − Rᵀ)ᵀ = Rᵀ − R = −(R − Rᵀ)   ⟹   skew-symmetric ✓
```

따라서 `log(R) = [ω̂]·θ` 는 다음 형태가 됩니다:

```
[ω̂]θ = ┌  0   -ω₃   ω₂ ┐
       │  ω₃   0   -ω₁ │ · θ        ← 대각=0, 위/아래 부호 반대 = skew
       └ -ω₂   ω₁   0  ┘
```

즉 **so(3) = "3×3 반대칭 행렬들의 집합"** 그 자체입니다.

> ⚠️ **미묘한 구분**: `SO3.log` 는 사실 **벡터** ω∈ℝ³ 를 돌려줍니다(`vee` 적용).
> - **행렬** 로그 `[ω̂]θ` → skew-symmetric 행렬 (so(3) 원소)
> - 거기에 **`vee`** → 3D 벡터 (코드가 실제 반환하는 것)
>
> `so(3) ≅ ℝ³` 동형 때문에 둘은 같은 정보이고, `hat`/`vee`로 오갑니다.

### A.3 SE(3)는 다르다 — twist는 skew가 아니다

반대로 `T ∈ SE(3)` 의 로그 `log(T) ∈ se(3)` 는 **skew-symmetric이 아닙니다.**

```
log(T) = ┌ [ω̂]θ   v ┐     ← 좌상단 3×3 블록만 skew,
         └  0     0 ┘        전체 4×4는 skew 아님 (twist)
```

그래서 `SE3.log` 는 `(twist·θ, screw, θ)` 를 반환합니다.
**"로그 = skew" 는 순수 회전(SO(3))에서만 성립**하고, 강체변환에서는
"좌상단 회전 블록만 skew" 인 twist가 나옵니다.

### A.4 요약

| 연산 | 입력 | 출력 | skew? |
|------|------|------|-------|
| `SO3.log(R)` | R ∈ SO(3) | [ω̂]θ ∈ so(3) | ✅ **skew-symmetric** |
| `SE3.log(T)` | T ∈ SE(3) | twist ∈ se(3) | ❌ (좌상단 블록만 skew) |
| `SO3.exp(ω)` | ω ∈ so(3) | R ∈ SO(3) | — (Rodrigues) |
| `SE3.exp(...)` | screw ∈ se(3) | T ∈ SE(3) | — |
